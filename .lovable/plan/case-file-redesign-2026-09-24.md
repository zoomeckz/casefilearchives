# Case File redesign

## Direction
- Rebrand the site as **CASE FILE** and remove all visitor- and admin-facing Sedorium branding.
- Replace the old subtitle with **UNRELATED STORIES. UNCOMFORTABLE POSSIBILITIES.**
- Apply the selected dossier-noir direction: editorial case folders, restrained red classification accents, sharp typography, and story artwork as evidence imagery.

## Public experience
- Rebuild the home page around the CASE FILE identity, a clear Start Reading action, and a case-file grid for recent stories.
- Restyle the Stories, Reader, About, profile, account, navigation, and footer screens as one consistent publication.
- Keep tags, reading time, dates, bookmarks, reading progress, subscriptions, sign-in, Google login, and account registration working.
- Keep Rewards, forums, Codex, translations, and other archived sections hidden without deleting their data or underlying functionality.

## Themes
- Add a visible light/dark theme switch that remembers the visitor’s choice and follows their system preference on first visit.
- Use a pale paper/archive treatment in light mode and a charcoal evidence-room treatment in dark mode, with accessible contrast in both.
- Carry the same theme tokens and controls into the admin panel, editors, dialogs, and account screens.

## Admin and publishing
- Restyle the admin shell and publishing tools to match CASE FILE while preserving all existing story, scheduling, tags, analytics, account statistics, and Legacy controls.
- Keep legacy chapters isolated in the existing Legacy area and avoid exposing their old branding publicly.

## Search presence
- Replace the old name and description in page titles, metadata, structured data, static story pages, sitemap-adjacent copy, notification copy, downloads, and crawler-facing text.
- Preserve the existing domain and story URLs so indexed links and reader history continue to work.

## Verification
- Check desktop and mobile layouts in light and dark modes.
- Test sign-in and registration entry points, story opening/filtering, theme persistence, admin navigation, editing, and scheduling.
- Run focused tests and confirm the final build is healthy.
